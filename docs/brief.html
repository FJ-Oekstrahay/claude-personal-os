claude-personal-os Overview
Brief

What I've been doing with Claude Code — and whether Anthropic made it pointless.

The short version, for engineers. Hardware background; daily driver is Claude Code on a Mac Mini, observed from a phone via Discord.

01

The Question Worth Asking First

Anthropic shipped a lot in 2026: SKILL.md auto-loading, auto-memory, native parallel multi-agent orchestration, background agents, a SubagentStop hook. Several of those overlap with things this config was doing in bespoke form. So: does any of it still need to exist?

Nothing is being ripped out, and the reason isn't inertia. What Anthropic shipped is infrastructure — mechanisms for loading, dispatching, and remembering. What's here is opinion, operational constraint, and production-hardened pattern. Those layers don't compete; they sit on top of each other. The mechanism becoming native doesn't make the opinion generic.

The honest accounting, section by section:

02

Hooks

Two production hooks. Both exist for reasons Anthropic hasn't addressed.

protect-sensitive-files.sh fires on Write, Edit, and Bash. It inspects tool input, extracts file paths, and blocks writes to protected paths — live config containing tokens, credential files, service plists. The Bash matcher is required because a Write|Edit matcher misses cp, tee, and redirects — those embed the path in a shell command string, not a top-level tool argument. Exit code must be 2; exit 1 does not block. Native tool permissions can restrict tool types. They cannot block writes to specific file paths inside Bash commands. That's the gap this fills.

discord-notify.sh streams every session to Discord in real time: narrative text before each tool call, a one-line summary after. Subagent dispatches post the full prompt (capped at ~1500 chars). Approval requests generate @mentions. Per-project channel routing — different directories bind to different webhooks. The result: I can see what Claude intends to do before it does it, and approve things, from a phone. Background agents deliver results when the session finishes. That's a different observability model than pre-call visibility, and pre-call visibility is the part that matters operationally.

Routing inbound messages to the right session is handled by a separate component: a Node.js/TypeScript bot (~/.claude/discord-router/router.ts) that connects to Discord's Gateway via discord.js and maps channels to sessions via a routes.json file. One bot process handles all Claude Code sessions — not one bot per session. Per-channel access is enforced via access.json. This is the infrastructure layer that makes multi-session Discord access possible; the MCP plugin and the hook both assume it's running.

03

Skills

SKILL.md auto-loading is now native — Anthropic adopted the format this config uses. The mechanism is theirs now. The content of the skills is still the work.

review-sequence runs Gadfly before CTO. The ordering is causal, not a parallelization shortcut. Gadfly is a hostile product skeptic — looks for wrong assumptions about what users actually want. CTO reviews build sequence and architectural coherence. If CTO runs first, it produces a structural plan that anchors everything; Gadfly's objections come too late to change the architecture. Native parallel dispatch runs them concurrently, producing two independent reviews that must be synthesized. Sequential Gadfly-then-CTO produces CTO output that already incorporates Gadfly's findings as input. Those are different things. The sequencing is enforced explicitly because the platform won't enforce it for you.

batchc is a parallel subagent dispatch protocol. The pattern: identify independent tasks, set wave size based on context budget and rate-limit exposure, dispatch in parallel, merge before the next wave. The merge constraint exists because downstream agents working on stale intermediate state produce coherent-looking results that are wrong in ways that are hard to catch in review. Native orchestration provides the mechanism; wave discipline and merge-before-parallelize are still judgment calls that need encoding.

mmguns is a research-to-integration loop: four-angle parallel web search, project inventory, gap analysis, ranked brief of three items, dispatch action. Quick wins confirm then implement; medium lifts generate a spec stub. The loop always closes — it never produces a report that requires another decision about what to do with it. Anthropic hasn't shipped anything structurally similar.

There are also opinionated reviewer personas: Critic (harsh code review, no suggestions), Gadfly (product skeptic), CTO (architectural planner), debug-agent (failure-mode focused). The behavioral specifications matter — "ask Claude to review this from a product perspective" is not the same as Gadfly. The persona has to be persistent enough to actually push back.

04

Memory

Three layers. They do different things.

CLAUDE.md (always loaded) — behavioral rules, tool permissions, protected paths, and extracted errata. The errata section is the part worth explaining: hook exit code semantics (exit 2 blocks; exit 1 does not), hook matcher scope (tool names, not file operations — Bash must be in the matcher), file staging risk (a file named identity/device.json contained a plaintext private key). These are in the always-loaded layer because they cause silent failures. By the time a retrieval system surfaces them, the mistake has already happened.

Playbook library (~359 files) — curated domain knowledge indexed by keyword. Betaflight serial quirks, Claude Code API behavior, macOS gotchas, hook semantics. Each entry records what broke, why, and how to apply the lesson. Anthropic shipped auto-memory in February 2026. Auto-memory writes what Claude observes during a session. The playbook library records lessons from debugging failures that someone had to diagnose and write down in transferable form. Those are different things; one doesn't replace the other.

memsearch — a Claude Code plugin (v0.4.4) with local ONNX bge-m3 embeddings (no external API) and a Milvus-lite 2.5 vector store at ~/.memsearch/milvus.db. A stop hook auto-captures session transcripts for indexing. Semantic search over captured sessions and the playbook library. Relevant playbooks surface as hints at session start based on what the session is working on. Separate from OpenClaw's memory-lancedb plugin, which provides per-agent vector memory within the multi-agent system and uses SQLite internally — same storage layer, different scope.

Custom MCP memory server — a local stdio MCP server (mcp-memory-server.py, ~160 lines) that exposes the playbook library as a queryable wiki via three tools: list_memory() (compact index, ~500 tokens), get_memory(name) (full file), search_memory(query) (keyword grep over ~240 markdown files, ~50ms). Not native to Claude Code — registered as an MCP server in the session config. Preferred over memsearch for playbook lookup because playbooks are structured domain knowledge where keyword precision beats semantic similarity. The two tools serve different query types against the same library.

The Repo

The config is published at fj-oekstrahay.github.io/claude-personal-os. Auto-synced nightly from ~/.claude with a redaction pass. The interesting parts aren't the mechanism — they're the content of the skills, the errata in LESSONS.md, and the decisions that went into the hook semantics.

The public repo has the actual config, selected playbooks, and the sync script: github.com/fj-oekstrahay/claude-personal-os
