claude-personal-os Overview
Brief

What I've been doing with Claude Code.

The short version, for engineers. Hardware background; daily driver is Claude Code on a Mac Mini, observed from a phone via Discord.

01

The Config Layer

Claude Code exposes hooks, skills, and MCP as configuration primitives. I've been building a behavioral layer on top of those: rules that load on every session, hooks that enforce operational constraints, skills that encode cognitive workflows rather than generic prompts, and a memory system that spans multiple timescales.

The config is published at fj-oekstrahay.github.io/claude-personal-os. Auto-synced nightly from ~/.claude with a redaction pass. The interesting parts aren't the mechanism — they're the content of the skills, the errata in LESSONS.md, and the decisions that went into the hook semantics.

02

Hooks

Two production hooks.

protect-sensitive-files.sh fires on Write, Edit, and Bash. It inspects tool input, extracts file paths, and blocks writes to protected paths — live config containing tokens, credential files, service plists. The Bash matcher is necessary because a Write|Edit matcher misses cp, tee, and redirects. Exit code must be 2 — exit 1 does not block. This took a production incident to learn.

discord-notify.sh streams every session to Discord in real time: narrative text before each tool call, a one-line summary after. For subagent dispatches it posts the full prompt (capped at ~1500 chars). Approval requests generate @mentions in the conversation channel. Per-project channel routing — different directories bind to different webhooks. The practical effect: I can see what Claude is doing and approve things from my phone without a terminal open.

03

Skills

Skills auto-load via SKILL.md — Anthropic adopted that format, which is the same one this config uses. The mechanism is now native. The content is still the work.

review-sequence runs Gadfly before CTO. Gadfly is a hostile product skeptic — looks for wrong assumptions about what users actually want. CTO reviews build sequence and architectural coherence. The ordering is causal: if CTO runs first, it produces a structural plan that anchors everything; Gadfly's objections come too late to change the architecture. Native parallel dispatch runs them concurrently and loses this. The sequencing is enforced explicitly.

batchc is a parallel subagent dispatch protocol. The pattern: identify independent tasks, set wave size based on context budget and rate-limit exposure, dispatch in parallel, merge before the next wave. The "merge before parallelize" constraint exists because downstream agents working on stale intermediate state produce coherent-looking results that are wrong in subtle ways.

mmguns (Make More Good Use New Stuff) is a research-to-integration loop: four-angle parallel web search, project inventory, gap analysis, ranked brief of three items, dispatch action. Quick wins ask for confirm then implement; medium lifts generate a spec stub. The loop always closes — it doesn't produce a document that requires another decision about what to do with it.

There are also opinionated reviewer personas: Critic (harsh code review, no suggestions), Gadfly (product skeptic), CTO (architectural planner), debug-agent (failure-mode focused). The personas have behavioral constraints that make them actually push back rather than hedge.

04

Memory

Three layers operating at different timescales.

CLAUDE.md (always loaded) — behavioral rules, tool permissions, protected paths, and LESSONS.md. The lessons section is extracted errata from production: hook exit code semantics, hook matcher scope, file staging risk (a file named identity/device.json contained a plaintext private key). These are in the always-loaded layer because they cause silent failures — by the time memsearch would surface them, the mistake has already happened.

Playbook library (~359 files) — curated domain knowledge indexed by keyword. Betaflight serial quirks, USB HID gadget mode on macOS, Claude Code API behavior, macOS gotchas, hook semantics. Each entry records what broke, why, and how to apply the lesson. Anthropic shipped auto-memory in February 2026, which writes session observations. These are different things: auto-memory records what Claude notices during a session; the playbook library records lessons from debugging failures that someone had to diagnose and write down in transferable form.

memsearch — local ONNX embeddings (bge-m3, ~558 MB, on-device) over session transcripts and the playbook library. Per-project isolation via per-git-root SQLite. Relevant playbooks surface as hints at session start based on what the session is working on.

05

What Anthropic Changed in 2026

Several things that were bespoke here are now native: SKILL.md loading, auto-memory, parallel multi-agent orchestration, SubagentStop hook, background agents via /bg. That's real, and it means the platform surface has grown substantially.

The pattern: Anthropic ships mechanisms; the bespoke config provides the content and constraints that ride on top. Parallel orchestration doesn't specify when to merge before the next wave. Auto-memory doesn't produce curated domain knowledge from past debugging sessions. Skill loading doesn't determine whether Gadfly runs before or after CTO.

The Discord integration has no Anthropic equivalent. Real-time session streaming to an external chat platform with per-project channel routing and approval @mentions is not a platform feature — it's a bespoke operational requirement that happens to be fully achievable with hooks and MCP.
