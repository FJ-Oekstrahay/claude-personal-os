# commands/

Slash commands: markdown files that Claude Code loads and executes when the user types `/<name>`
(or, for `caution`, `orchcheck`, and `longrun`, when the bare trigger word appears; those three are
also reachable via `discord-keyword-dispatch.py` for dictation and mobile Discord, where typing `/`
isn't natural). Each file is the literal instructions Claude follows for that command; there is no
separate implementation.

| File | What it does |
|---|---|
| `batchc.md` | Smartbatch execution protocol. Reads current session resource pressure first, then classifies each item in a request into inline-answer / parallel-dispatch / sequential / Cob-subagent buckets and paces waves according to pressure level. |
| `become-expert.md` | Three-pass expertise builder for a named domain: researches to current standard, writes a persona file (identity, analytical framework, standards of evidence, blind spots, falsifiability), then applies that lens to the task at hand. |
| `caution.md` | Standing procedure triggered by the word "caution": enumerates other active Claude Code sessions on the machine, classifies subtasks as safe-to-do-now vs. defer based on collision risk with those sessions' working directories and shared live surfaces, and writes deferred work to a prompt file rather than guessing. |
| `load-handoff.md` | Loads a previous session's handoff file. If the session is Discord-bound, matches by thread/channel ID first (a project can accumulate handoffs from several unrelated threads); otherwise lists the most recent handoffs for the user to pick from. |
| `longrun.md` | Drains a feature queue with model-routed workers. A mode argument (`go`, `go cross`, `go unattended`, `status`, `add`) is required before anything executes; the bare command only plans and reports the queue. |
| `memory-health.md` | Runs a script that reports a compact status table on four memory-related tiers: auto-memory, memsearch, the session-pressure state file, and the hook-errors log. |
| `mmguns.md` | Research-to-integration workflow for a named capability area: surveys the current state of the art, compares it against the project's actual stack, and drives immediate action. A quick win gets implemented, a medium lift gets a spec stub, a non-starter gets ruled out with reasoning. |
| `orchcheck.md` | Pauses before executing a task to classify it against the orchestration decision tree (inline, parallel dispatch, batchc, or Workflow) and waits for a go-ahead rather than running it. |
| `plan-session.md` | Reads the most recent handoff plus any open-topics or project-board files and proposes a batchc wave plan for the session. Stops for approval; dispatches nothing. |
| `platform-expert.md` | Bootstraps competence on an unfamiliar development platform from zero: surveys first-party, bundled, and third-party capability surfaces, pins a toolchain, and produces a phased prompt set so the buildout survives across sessions. |
| `pressure.md` | Manually overrides the tracked resource-pressure level (`normal`, `elevated`, `high`) for the current session only; `/pressure normal` clears the override. |
| `prompt-sweep.md` | Sweeps a project's `prompts/` directory, assesses each prompt's completion status (done / pending / in-progress / standing), and archives the ones that are done. |
| `review-sequence.md` | Multi-role adversarial review protocol: a decision tree for which of Critic, Gadfly, Architect, or CTO to run and in what order, plus a model-escalation table for when to bump a reviewer to Opus. |
| `session-handoff.md` | Writes a session handoff, after first checking whether one is actually warranted. Forces the timestamp in the output filename to be generated by the shell at rename time rather than typed by the model, to avoid wrong-dated filenames from UTC/local-timezone confusion. |

## Notes

- `caution`, `orchcheck`, and `longrun` are deliberately non-slash trigger words rather than
  `/command` syntax, so they can be typed or dictated into a Discord message and still be recognized
  by `discord-keyword-dispatch.py` (see `../hooks/README.md`).
- `review-sequence.md`'s sequencing rule (run Gadfly before CTO) is described in more detail in
  `../agents/README.md` and `../selected-playbooks/review_sequence_protocol.md`.
